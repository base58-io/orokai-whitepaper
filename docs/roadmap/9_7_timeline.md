## Development Phases

### Phase 1

- M2: Zero-setup wallet
- M4: Stripe on-ramp
- M4: Onramper on-ramp (backup)
- M5: V Plus Pay virtual card
- M5: Lido ETH staking
- M5: Cosmos ATOM staking
- M5: Solana SOL staking
- M6: Uniswap V3 swaps (EVM chains)
- M6: Raydium swaps (Solana)

### Phase 2

- M10: AAVE lending (Ethereum, Polygon)
- M10: AI Agent v1 (basic recommendations)
- M13: CCTP bridge (native USDC)
- M13: Wormhole or LayerZero bridge
- M15: Auto-claim (staking rewards)
- M15: Scheduled rebalancing
- M16: Wallet permission audits
- M16: Transaction history export (CSV/JSON)
- M18: Physical card (if V Plus Pay ready)

### Phase 3 (Conditional (may be delayed or cancelled))

-  M22: CEX lending (via partners, KYC required)
-  M24: Optional KYC flows (for regulated features)
-  M25: TGE (Token Generation Event)
-  M26: RWA integrations (tokenized assets via partners)
-  M28: OROKAI Chain testnet
-  M30: Token staking (on OROKAI Chain)
-  M33: OROKAI Chain mainnet v1
-  M34: Securities trading (highly conditional, may not launch)
-  M36: Enterprise API & white-label SDK

## IMPORTANT DISCLAIMER 
>
> This roadmap timeline is INDICATIVE and SUBJECT TO CHANGE.
>
>We provide these dates to communicate strategic direction and prioritization,
> NOT as binding commitments.

### Factors that may cause delays:
- Technical challenges requiring redesign
- Security findings in audits
- Partner readiness (outside our control)
- Regulatory developments
- Market conditions (bear market, user demand shifts)
- Team capacity (hiring delays, attrition)
- Unforeseen risks (see Section 9.7)

### We commit to:
> Transparent communication about changes

> Prioritizing quality and security over speed

> Delivering core value proposition (non-custodial DeFi aggregation)

> Listening to user feedback and adapting

### We do NOT commit to:
- Specific launch dates for any feature
- Completing every feature mentioned
- Never changing priorities
- Meeting timeline if safety is compromised

:::warning[statement]
Users, investors, and partners should treat this roadmap as a PLAN, not a GUARANTEE.
Actual results will vary. Past roadmap adherence (once we have history) is not
indicative of future performance.
:::
