# モニタリングと適応（ユーザーデータからの学習）

## モニタリングされるシグナル（例）

### ポジションステータス
オンチェーン状態、クレームステータス、目標配分からの偏差、ポジション維持コスト。

### プロトコルの変更
報酬/APRパラメータ、制限、警告、コントラクトバージョン。

### 運用リスク
ブリッジ/チェーンアラート、DEX異常（例：流動性、MEV影響を受けやすいルート）。

### モニタリングシグナル：AIが監視するもの
モニタリングされるシグナルとアラート閾値

> カテゴリ：利回りパフォーマンス

| シグナル | 閾値 | アラートタイプ | 緊急度 |
|--------|-----------|------------|---------|
| APY低下（あなたのプロトコル） | >10% | 警告 | 中 |
| APY低下（あなたのプロトコル） | >25% | 重大 | 高 |
| 代替APYの優位性 | >0.5% | 機会 | 低 |
| 報酬発生停止 | 24時間 | エラー | 高 |
| クレーム可能な報酬利用可能 | >50ドル | リマインダー | 低 |

> カテゴリ：リスクとセキュリティ

| シグナル | 閾値 | アラートタイプ | 緊急度 |
|--------|-----------|------------|---------|
| プロトコルセキュリティインシデント | 任意 | 重大 | 即時 |
| 監査のダウングレード | 任意 | 警告 | 高 |

| スマートコントラクトアップグレード | 任意 | 情報 | 低 |
| 類似プロトコルでのエクスプロイト | 任意 | 警告 | 中 |
| あなたのポジションが清算に近い | LTV >75% | 重大 | 即時 |

> カテゴリ：コスト最適化

| シグナル | 閾値 | アラートタイプ | 緊急度 |
|--------|-----------|------------|---------|
| ガス価格が平均以下 | 30% | 機会 | 低 |
| ガス価格急騰 | 平均の>2倍 | 警告 | 中 |
| ブリッジ混雑/高手数料 | >50ドル | 警告 | 低 |
| DEXスリッページ増加 | >1% | 警告 | 中 |

> カテゴリ：市場状況

| シグナル | 閾値 | アラートタイプ | 緊急度 |
|--------|-----------|------------|---------|
| ETH価格変動 | 24時間で±10% | 情報 | 低 |
| ステーブルコインのデペッグ | >1% | 重大 | 即時 |

| シグナル | 閾値 | アラートタイプ | 緊急度 |
|--------|-----------|------------|---------|

| ロックアップ期間終了 | 7日 | リマインダー | 低 |

> カテゴリ：新しい機会

| シグナル | 閾値 | アラートタイプ | 緊急度 |
|--------|-----------|------------|---------|
| 新しいプロトコルが審査を通過 | 任意 | 機会 | 低 |
| より高い利回り戦略利用可能 | >0.7%の優位性 | 機会 | 低 |
| インセンティブプログラム開始 | あなたに一致 | 機会 | 中 |
| より良い流動性オプション | -50%スリップ | 機会 | 低 |

ユーザーコントロール：
- シグナルタイプごとに閾値を調整
- 特定のアラートタイプを無効化
- 静寂時間を設定（午後10時～午前8時は通知なし）
- 配信方法を選択（アプリ内/メール/プッシュ/なし）
- 特定のポジションのアラートをスヌーズ（7/30/90日）

### 適応：AIがあなたから学ぶ方法
AI行動学習の例
```
シナリオ1：ユーザーが一貫して高リスクの提案を無視
─────────────────────────────────────────────────────────────────────
AIが観察：
- 5つ連続の「高APY」アラートを却下
- ユーザーはリスクスコア<60の提案のみを受け入れる

AIが適応：
✓ プロファイルでリスク許容度を下げる：バランス → 保守的
✓ リスク>65のプロトコルの表示を停止
✓ スコアリングで「安定性」要因の重みを増加
✓ ユーザーに通知：「より保守的なオプションを表示するように調整しました」
```
```
シナリオ2：ユーザーが常に低ガスを待つ
─────────────────────────────────────────────────────────────────────
AIが観察：
- ユーザーが4つのマイグレーションアラートをスヌーズ
- すべてガス<15 gweiで実行

AIが適応：
✓ ガス閾値トリガーを上げる：<15 gweiの時のみアラート（<25 vs）
✓ 「ガスアラート設定」機能の提案を追加
✓ 推奨でより長い待機時間を見積もる
✓ 即座の機会よりもガス節約を優先
```
```
シナリオ3：ユーザーはより高いコストにもかかわらずEthereumを好む
─────────────────────────────────────────────────────────────────────
AIが観察：
- ユーザーが3つのPolygon提案を拒否（低ガス）
- 常にEthereum代替案を選択

AIが適応：
✓ チェーンの好みを更新：Ethereum = 「強く好む」
✓ 推奨でPolygonの優先度を下げる
✓ 優位性>2% APYの場合のみPolygonを提案（0.5% vs）
✓ ユーザーがコスト節約よりもEthereumセキュリティを重視すると仮定
```
```
シナリオ4：ユーザーは自動複利機能を愛する
─────────────────────────────────────────────────────────────────────
AIが観察：
- ユーザーが10回以上報酬を手動で再ステーク
- 利用可能な場合は常に「自動複利」を有効化

AIが適応：
✓ ネイティブ自動複利を持つプロトコルを優先
✓ 自動化されたクレーム→再ステークフローの設定を提案
✓ 複利APY（単利APY vs）を計算してハイライト
✓ 自動複利するボールト（Yearnスタイル）を推奨
```
```
シナリオ5：ユーザーが重大アラートに迅速に応答
─────────────────────────────────────────────────────────────────────
AIが観察：
- 2つのセキュリティ警告に30分以内に対応
- 機会への平均応答時間：3日

AIが適応：
✓ ユーザーを「重大に応答」としてマーク
✓ セキュリティアラートのプッシュ通知を有効化（機会ではない）
✓ 真に重大なイベントにのみ緊急言語を使用
✓ 緊急でない提案を週次ダイジェストにまとめる
```
:::warning[重要な原則：]
✓ AIはあなたから学び、あなたのために学ぶのではありません（あなたが管理を維持）

✓ すべての適応は透明です（何が変わったかを確認できます）

✓ いつでもAIの学習された好みを上書きできます

✓ あなたの署名なしにアクションが実行されることはありません
:::


## 適応（原則）

### リバランス/マイグレーション提案
エージェントは重要な変更（例：報酬が閾値を下回る、プロトコルリスクの増加）について<mark>通知</mark>し、代替案を準備します。

### 通知モード
アプリ内 + オプションのメール/プッシュ（利用可能な場合）。

### ヒューマンインザループ
変更は自動的には発生しません。ユーザーが取引を承認し署名します。

## データとプライバシーに関する注意

学習には使用メトリクスとユーザーの選択が含まれます。<mark>必要な範囲を超える機密データは含まれません。</mark>データは、推奨品質を向上させるために集約/匿名化される場合があります。プライバシーポリシー文書に準拠したポリシー。

:::tip[透明な学習]

AI Agentはユーザーのインタラクションから学習し、時間の経過とともにより良い提案を提供しますが、決して自律的に行動しません – すべての決定には明示的なユーザー承認が必要です。

:::
