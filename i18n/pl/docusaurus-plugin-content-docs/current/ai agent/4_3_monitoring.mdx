# Monitoring i adaptacja (uczenie się z danych użytkownika)

## Monitorowane sygnały (przykłady)

### Status pozycji
Stan on-chain, statusy claimów, odchylenia od docelowych alokacji, koszty utrzymania pozycji.

### Zmiany protokołów
Parametry nagród/APR, limity, ostrzeżenia, wersje kontraktów.

### Ryzyko operacyjne
Alerty mostów/łańcuchów, anomalie DEX (np. płynność, trasy wrażliwe na MEV).

### Adaptacja: Jak AI uczy się od Ciebie
PRZYKŁADY UCZENIA BEHAWIORALNEGO AI
```
SCENARIUSZ 1: Użytkownik konsekwentnie ignoruje sugestie wysokiego ryzyka
─────────────────────────────────────────────────────────────────────
AI obserwuje:
- 5 kolejnych alertów „wysokiego APY" odrzuconych
- Użytkownik akceptuje tylko sugestie z oceną ryzyka <60

AI adaptuje:
✓ Obniżenie tolerancji ryzyka w profilu: Zbalansowane → Konserwatywne
✓ Przestań pokazywać protokoły z ryzykiem >65
✓ Zwiększ wagę czynnika „stabilności" w punktacji
✓ Powiadom użytkownika: „Dostosowaliśmy się, aby pokazywać bardziej konserwatywne opcje"
```
```
SCENARIUSZ 2: Użytkownik zawsze czeka na niższy gas
─────────────────────────────────────────────────────────────────────
AI obserwuje:
- Użytkownik odłożył 4 alerty migracji
- Wszystkie wykonane gdy gas <15 gwei

AI adaptuje:
✓ Podnieś próg wyzwalania gazu: Alert tylko gdy <15 gwei (vs <25)
✓ Dodaj sugestię funkcji „Ustaw alert gazu"
✓ Oszacuj dłuższe czasy oczekiwania w rekomendacjach
✓ Priorytetyzuj oszczędności gazu nad natychmiastową okazją
```
```
SCENARIUSZ 3: Użytkownik preferuje Ethereum mimo wyższych kosztów
─────────────────────────────────────────────────────────────────────
AI obserwuje:
- Użytkownik odrzucił 3 sugestie Polygon (niższy gas)
- Zawsze wybiera alternatywy Ethereum

AI adaptuje:
✓ Aktualizacja preferencji łańcucha: Ethereum = „Silnie preferowane"
✓ Depriorytetyzacja Polygon w rekomendacjach
✓ Sugeruj Polygon tylko jeśli przewaga >2% APY (vs 0,5%)
✓ Zakładaj, że użytkownik ceni bezpieczeństwo Ethereum nad oszczędności kosztów
```
```
SCENARIUSZ 4: Użytkownik uwielbia funkcje auto-składania
─────────────────────────────────────────────────────────────────────
AI obserwuje:
- Użytkownik ręcznie re-stakował nagrody 10+ razy
- Zawsze włącza „auto-składanie" gdy dostępne

AI adaptuje:
✓ Priorytetyzuj protokoły z natywnym auto-składaniem
✓ Sugeruj konfigurację automatycznych przepływów claim→re-stake
✓ Oblicz i podkreśl składane APY (vs. proste APY)
✓ Rekomenduj vaults (styl Yearn) z auto-składaniem
```
```
SCENARIUSZ 5: Użytkownik szybko reaguje na krytyczne alerty
─────────────────────────────────────────────────────────────────────
AI obserwuje:
- Użytkownik działał w ciągu 30 min po 2 ostrzeżeniach bezpieczeństwa
- Średni czas reakcji na okazje: 3 dni

AI adaptuje:
✓ Oznacz użytkownika jako „Responsywny na krytyczne"
✓ Włącz powiadomienia push dla alertów bezpieczeństwa (nie dla okazji)
✓ Używaj pilnego języka tylko dla prawdziwie krytycznych zdarzeń
✓ Grupuj niepilne sugestie w tygodniowy digest
```
:::warning[WAŻNE ZASADY:]
✓ AI uczy się OD ciebie, nie ZA ciebie (zachowujesz kontrolę)

✓ Wszystkie adaptacje są transparentne (możesz zobaczyć co się zmieniło)

✓ Możesz nadpisać nauczone preferencje AI w każdej chwili

✓ Żadna akcja nie jest wykonywana bez Twojego podpisu
:::

## Adaptacja (zasady)

### Propozycje rebalansowania/migracji
Agent <mark>informuje</mark> o istotnych zmianach (np. nagrody spadają poniżej progu, zwiększone ryzyko protokołu) i przygotowuje alternatywy.

### Tryby powiadomień
W aplikacji + opcjonalne email/push (gdzie dostępne).

### Human-in-the-loop
Żadne zmiany nie zachodzą automatycznie; użytkownik akceptuje i podpisuje transakcje.

## Uwaga dotycząca danych i prywatności

Uczenie obejmuje metryki użycia i wybory użytkownika; <mark>nie obejmuje danych wrażliwych poza niezbędnym zakresem.</mark> Dane mogą być agregowane/anonimizowane w celu poprawy jakości rekomendacji; polityka zgodna z dokumentem Polityki Prywatności.

:::tip[Transparentne uczenie]

Agent AI uczy się z interakcji użytkownika, aby zapewniać lepsze sugestie z czasem, ale nigdy nie działa autonomicznie – wszystkie decyzje wymagają wyraźnej zgody użytkownika.

:::
